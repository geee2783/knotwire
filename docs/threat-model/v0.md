# Threat model v0 (M0)

Assets and boundaries to design to; not a complete ASVS audit.

## Assets
- Per-tenant OAuth tokens (WhatsApp WABA, Facebook Page, generic API keys)
- Message contents (WA/FB) and PII in leads/contacts
- Bot/agent JSON definitions (intellectual property of the operator)
- Webhook signing secrets (inbound verification, outbound HMAC)

## Top risks and mitigations

| # | Risk | Mitigation (milestone) |
|---|---|---|
| T1 | Cross-tenant data access (shared schema) | Postgres RLS + `SET LOCAL app.tenant_id`; `assertTenant()` double-check; isolation tests in CI (M0–M1) |
| T2 | Credential vault compromise | Envelope encryption, KMS/master key from env or KMS; no plaintext tokens in DB (M2) |
| T3 | SSRF via outbound webhooks/bot HTTP actions | Egress allow-list, block RFC1918/metadata ranges, HMAC signing (M1/M6) |
| T4 | Prompt injection in WhatsApp messages → LLM agent | Tool allow-list, side-effect approvals, KB-source quoting instead of raw page dumps, evals (M5) |
| T5 | WhatsApp template/24h-window policy violations | Template moderation client; window tracking; opt-out registry (M2) |
| T6 | Token replay/webhook forgery (Meta) | X-Hub-Signature-256 verification; constant-time compare; replay window (M2/M3) |
| T7 | Debug endpoints leak data | /healthz & /readyz only; no dump routes; production log redaction (M0+) |
| T8 | Supply chain | lockfile, `npm ci`, SBOM in CI; dependency license gate (M0) |
| T9 | Secret in repo | gitleaks in CI (pre-push); `.env` ignored |
| T10 | Tenant deletion/GDPR incomplete | First-class tenant export/delete commands; tested (M1) |

## Non-goals (M0)
No VoIP, no billing, no hosted multi-customer SaaS. Tailscale profile (M6):
loopback-only default bind; Funnel requires explicit operator action.
